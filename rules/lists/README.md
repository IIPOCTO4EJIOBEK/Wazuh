# Списки CDB

Списки — это способ вынести перечни из правил. Правило проверяет
принадлежность значения списку, а сам перечень правится без пересборки
и перезапуска логики обнаружения.

## Формат

Строго `ключ:значение`, по одной паре в строке. Комментарии и пустые
строки не допускаются — `wazuh-makelists` на них ругается, а частично
собранный список молча ломает правила, которые на него ссылаются.

Значение может быть пустым (`ключ:`), но двоеточие обязательно.

## Файлы

| Файл | Ключ | Значение | Где используется |
|------|------|----------|------------------|
| `ahp-privileged-users` | учётная запись | назначение | 100020, 100305, 100330 |
| `ahp-critical-hosts` | имя агента | роль узла | 100005, 100230, 100240 |
| `malicious-ioc/malware-hashes` | SHA256 | откуда взят хеш | 100522 |

`malicious-ioc/malware-hashes` ведётся в репозитории и перезаписывается
при прогоне плейбука — добавленное руками на узле пропадёт. Значение
служит пометкой об источнике: `winexesvc-pdc-hv0-20260701` читается как
«из отчёта сканирования pdc-hv0 от 01.07.2026». Соседние файлы того же
каталога, `malicious-ip` и `malicious-domains`, наоборот, ведутся на
узле из внешних лент, и плейбук их не трогает.

`ahp-privileged-users` работает в обе стороны: правило 100305 срабатывает
на вход **из** списка (привилегированная запись зашла на рабочую станцию),
а правила 100020 и 100330 — на действие **вне** списка (обычный
пользователь получил права).

Поэтому при добавлении новой служебной учётной записи в список нужно
понимать: она перестанет попадать под 100020 и начнёт попадать под 100305.

## Сборка

Списки компилируются в бинарный формат при перезапуске менеджера или
вручную:

```bash
/var/ossec/bin/wazuh-makelists
```

Проверка, что список собран и виден правилам:

```bash
ls -la /var/ossec/etc/lists/ahp-critical-hosts.cdb
/var/ossec/bin/wazuh-logtest   # прогнать событие с нужным agent.name
```

## Что сюда не входит

`ar-never-block.txt` — не список CDB. Это обычный текстовый файл с
сетями, который читают скрипты active response напрямую. Он собирается
Ansible из переменной `wazuh_ar_never_block` и в правилах не участвует.
