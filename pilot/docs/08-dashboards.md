# 08. Дашборды

## Что есть

Три дашборда AH Prostory плюс штатные дашборды Wazuh (обзор, MITRE,
целостность файлов, соответствие требованиям, уязвимости) — последние
приходят с продуктом и здесь не описываются.

### AH Prostory — обзор SOC

Первый экран дежурного. Период по умолчанию — сутки, обновление раз в
минуту.

| Панель | Что показывает | Как читать |
|--------|----------------|-----------|
| Инциденты уровня 12+ | число за период | больше нуля — есть работа |
| Поток событий по уровням | гистограмма по времени | провал при живых агентах — потеря событий, а не тишина |
| Узлы по числу событий | доли | один узел на 60% графика — он либо атакован, либо шумит |
| Самые частые срабатывания | таблица правил | правило в верхней строке неделями — кандидат на настройку |
| Техники MITRE ATT&CK | столбцы | что пытались сделать, а не сколько раз сработало правило |
| Отказы аутентификации | адрес → узел | подбор паролей виден здесь раньше, чем в алертах |

Про провал на графике стоит сказать отдельно. Интуиция подсказывает,
что меньше событий — это хорошо. На практике резкое падение потока при
неизменном числе активных агентов означает переполнение очереди
analysisd или остановку filebeat. Тишина в SIEM — почти всегда
неисправность, а не спокойствие.

### AH Prostory — инфраструктура и реагирование

Период по умолчанию — неделя.

| Панель | Что показывает |
|--------|----------------|
| Изменения файлов портала | путь, тип события, узел |
| Автоматическое реагирование | что заблокировано, кого изолировали, результат |
| Изменения в Active Directory | создание записей, изменения групп |
| События дисковой подсистемы | отказы хранилища и служб |
| Резервное копирование | задание, назначение, результат |

В таблице реагирования отдельно смотреть строки с результатом
`skipped-allowlist`: сработала защита от блокировки собственной
инфраструктуры. Это повод проверить, не слишком ли широко написано
правило.

### AH Prostory — уязвимости

Период — месяц. Источник данных — инвентарь syscollector,
сопоставленный с базами CVE. Индекс отдельный:
`wazuh-states-vulnerabilities-*`.

Показывает распределение по критичности и таблицу «узел → пакет → CVE».
Практический порядок работы: раз в месяц выгрузить критические и
высокие, сопоставить с планом обновлений, остальное — в отчёт.

## Как менять

Дашборды собираются генератором, а не правятся в интерфейсе.

```bash
cd wazuh-deploy/dashboards
$EDITOR build_saved_objects.py
python3 build_saved_objects.py
./import-dashboards.sh
```

Причина: файл экспорта — несколько тысяч строк JSON, вложенного в JSON.
Править его руками нельзя, сравнивать в истории изменений бессмысленно,
а опечатка обнаруживается только при импорте. В генераторе описание
одной панели занимает десять строк и читается.

Идентификаторы объектов детерминированные — считаются из имени. Поэтому
повторный импорт обновляет те же объекты, а не плодит копии.

Через Ansible:

```bash
cd ../ansible
ansible-playbook site.yml --tags saved-objects --ask-vault-pass
```

### Если дашборд правили в интерфейсе

Изменения останутся в индексе `.kibana` и будут перезаписаны при
следующем импорте. Чтобы сохранить их в репозитории — выгрузить и
перенести в генератор:

```bash
curl -sk -u admin -X POST \
  'https://wazuh.ahprostory.ru/api/saved_objects/_export' \
  -H 'osd-xsrf: true' -H 'Content-Type: application/json' \
  -d '{"type":["dashboard","visualization"],"includeReferencesDeep":true}' \
  -o экспорт.ndjson
```

## Отчёты

### Регулярные

| Отчёт | Периодичность | Как получить |
|-------|---------------|--------------|
| Сводка инцидентов | еженедельно | дашборд обзора, период 7 дней, «Generate PDF» |
| Уязвимости | ежемесячно | дашборд уязвимостей |
| Покрытие агентами | ежемесячно | модуль Wazuh → Agents |
| Соответствие CIS | ежеквартально | модуль Wazuh → Security configuration assessment |

### Выгрузка данных запросом

Число инцидентов уровня 12+ по узлам за месяц:

```bash
curl -sk -u admin -H 'Content-Type: application/json' \
  'https://10.5.2.81:9200/wazuh-alerts-*/_search?pretty' -d '{
  "size": 0,
  "query": {"bool": {"filter": [
    {"range": {"timestamp": {"gte": "now-30d"}}},
    {"range": {"rule.level": {"gte": 12}}}
  ]}},
  "aggs": {"по_узлам": {"terms": {"field": "agent.name", "size": 50}}}
}'
```

Что заблокировало активное реагирование за неделю:

```bash
curl -sk -u admin -H 'Content-Type: application/json' \
  'https://10.5.2.81:9200/wazuh-alerts-*/_search?pretty' -d '{
  "size": 100,
  "query": {"bool": {"filter": [
    {"range": {"timestamp": {"gte": "now-7d"}}},
    {"term": {"rule.groups": "active_response"}}
  ]}},
  "_source": ["timestamp", "agent.name", "data.ar.action", "data.ar.target", "data.ar.result"]
}'
```

## Доступ

| Учётная запись | Права | Кому |
|----------------|-------|------|
| `admin` | полный доступ | администратор платформы |
| `auditor` | только чтение алертов и дашбордов | аудиторы, смежные подразделения |
| `kibanaserver` | служебная | дашборд → индексер |
| `filebeat` | запись алертов | менеджеры → индексер |
| `snapshotter` | снапшоты | задание резервного копирования |

Под `admin` в интерфейсе работать не следует: это учётная запись для
`securityadmin.sh` и разбора инцидентов. Для повседневной работы
создать именные записи с ролью `wazuh_reader` или `kibana_user`:

```bash
curl -k -u admin -X PUT 'https://10.5.2.81:9200/_plugins/_security/api/internalusers/petrov' \
  -H 'Content-Type: application/json' \
  -d '{"password":"...","backend_roles":["wazuh_reader"]}'
```

Именные записи важны не ради формальности: аудит обращений к индексеру
включён, и в журнале должно быть видно, кто именно смотрел данные.
