# Wazuh в сети AH Prostory

Развёртывание системы обнаружения и реагирования на инциденты
информационной безопасности: сбор событий со всей инфраструктуры,
анализ, дашборды, автоматическое реагирование и резервирование на всех
уровнях.

Проект рассчитан на существующую сеть компании: Bitrix-портал,
Active Directory, Hyper-V, MSSQL, ServiceDesk Plus и Zabbix. Правила
обнаружения написаны под эти системы, а не взяты из общего набора.

## Быстрый старт

Пилот (одна машина, без отказоустойчивости) разворачивается своим
инвентарём — см. [docs/14-pilot.md](docs/14-pilot.md):

```bash
ansible-playbook -i inventory/pilot/hosts.yml site.yml --ask-vault-pass
```

Отказоустойчивый комплект:

```bash
cd ansible

# 1. Секреты
cp group_vars/vault.yml.example group_vars/vault.yml
$EDITOR group_vars/vault.yml
ansible-vault encrypt group_vars/vault.yml

# 2. Проверка: инвентарь, доступность, ресурсы
ansible-playbook site.yml --tags preflight --ask-vault-pass

# 3. Установка целиком
ansible-playbook site.yml --ask-vault-pass

# 4. Агенты на Linux-серверы
ansible-playbook playbooks/agents-linux.yml --ask-vault-pass

# 5. Приёмка
../scripts/healthcheck.sh
```

Агенты Windows раскатываются групповой политикой, а не Ansible —
см. [docs/06-agents.md](docs/06-agents.md).

Полный порядок работ с проверками на каждом шаге:
[docs/03-installation.md](docs/03-installation.md).

## Границы решения

Стоит сказать прямо, чего эта установка не делает.

**Сетевой трафик не анализируется.** Wazuh работает с журналами узлов.
Атака, не оставившая следа в журналах ни одной машины (например, между
двумя узлами без агентов), останется незамеченной. Для полноты картины
нужен сетевой сенсор, это отдельная задача.

**Автоматическое реагирование ограничено намеренно.** Изоляция
применяется только к рабочим станциям, блокировка учётной записи — только
к непривилегированным и не чаще трёх раз в час. Причины и способ
изменения порогов — в [docs/07-detection-response.md](docs/07-detection-response.md).

**Резервирование не защищает от площадки целиком.** Все девять машин
стоят в одной сети. Копии конфигураций выгружаются наружу через rclone,
но снапшоты индексов остаются на площадке. Восстановление после потери
площадки означает восстановление конфигураций и потерю исторических
событий. Как это снять, разнеся узлы по площадкам, —
[docs/12-geo-distribution.md](docs/12-geo-distribution.md).

**Правила покрывают известные системы компании.** Появление новой
системы требует новых правил, иначе её события будут собираться, но не
анализироваться.
