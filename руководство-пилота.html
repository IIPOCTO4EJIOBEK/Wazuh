1

Виртуальная машина

Валерий 1–2 ч

Одна машина на pdc-hv0. Вторая (сборщик событий Windows) при выбранном способе подключения Active Directory не нужна.

ПараметрЗначениеПочему так
ОСUbuntu Server 24.04 LTSминимальная установка, без графики
vCPU8разбор событий правилами упирается в процессор
ОЗУ16 ГБфиксированная, не динамическая
Диск 160 ГБ/ — система
Диск 2250 ГБ/var/lib/wazuh-indexer
Диск 3100 ГБ/var/ossec
Сеть1 vNIC, статикасерверная Москвы

Три отдельных диска, а не один на 410 ГБ

Переполнение индексами на корневом томе останавливает всю операционную систему, а не только поиск. Каталог менеджера отдельно, потому что туда пишется буфер, когда индексер недоступен. Предполётная проверка откажется ставить систему, если тома совмещены, — и это сделано намеренно.

Создание на Hyper-V — одной командой

Скрипт снимает четыре настройки Hyper-V по умолчанию, которые здесь мешают: динамическую память, шаблон Secure Boot, автоматические контрольные точки и синхронизацию времени от гипервизора. Каждая пояснена в самом скрипте. 

# На pdc-hv0, в консоли от администратора
.\New-WazuhPilotVM.ps1 -SwitchName "SET-Wazuh" `
                       -Path       "D:\Hyper-V" `
                       -IsoPath    "D:\ISO\ubuntu-24.04-live-server-amd64.iso" `
                       -StartAfterCreate

# Той же командой создаются узлы отказоустойчивой схемы,
# отличаются только объёмы:
.\New-WazuhPilotVM.ps1 -Name wazuh-idx-01 -IndexerDiskGB 1024 `
                       -SwitchName "SET-Wazuh" -Path "D:\Hyper-V" `
                       -IsoPath "D:\ISO\ubuntu-24.04-live-server-amd64.iso"

Скрипт проверяет наличие коммутатора, образа и места на томе, а если машина с таким именем уже есть — ничего не пересоздаёт.

Подготовка ОС — одной командой

Скрипт делает всё, что должно быть готово до Ansible: размечает и монтирует тома по UUID, ставит имя узла, настраивает время, заводит учётную запись с ключом и sudo без пароля, обновляет пакеты. Повторный запуск ничего не ломает и диски не переразмечает. 

# Скопировать на машину и запустить от root
scp scripts/pilot/prepare-ubuntu-node.sh root@<адрес>:/tmp/
ssh root@<адрес>

chmod +x /tmp/prepare-ubuntu-node.sh
/tmp/prepare-ubuntu-node.sh     --indexer-disk /dev/sdb     --ossec-disk   /dev/sdc     --ssh-key      "$(cat ~/.ssh/id_ed25519.pub)"     --hostname     wazuh-pilot     --ntp          <адрес NTP домена>

Диски смотреть командой lsblk. Форматирование необратимо, поэтому скрипт отказывается трогать диск, на котором уже есть файловая система или разделы, и никогда не трогает системный. Осознанная переразметка — ключом --force.

Что скрипт сделает и что останется проверить

  • Три тома смонтированы, записи в /etc/fstab есть
  • Статический адрес, шлюз и DNS настроены, имя узла wazuh-pilot
  • Время синхронизировано: timedatectl show -p NTPSynchronized отдаёт yes
  • apt update && apt upgrade выполнены
  • Учётная запись ansible создана, ключ добавлен, sudo без пароля
  • Снимок состояния сделан — откат перед повторной установкой
  • Порты открыты: 514/tcp с сетей контроллеров домена и Bitrix; 443 и 22 с рабочих мест ИТ; наружу 443 и 10051 на Zabbix

Шаг выполнен, если

С управляющей машины проходит ssh ansible@<адрес> sudo -n true без запроса пароля, а df -h показывает три отдельных тома. Фактический адрес машины сообщить — он вписывается в инвентарь пилота.

Расширенный аудит на контроллерах домена

Дулепов 30 мин

Идёт параллельно с первым шагом и машины не ждёт. Без этих политик события 4688, 4769 и 4104 не создаются вовсе — собирать будет нечего, каким бы способом события ни доставлялись.

Быстрый путь: скрипт

Применяет всё сразу и проверяет результат чтением обратно. На пилоте из двух контроллеров этого достаточно. 

# На каждом контроллере домена, от администратора
.\Enable-AdAuditPolicy.ps1

# Посмотреть текущее состояние, ничего не меняя
.\Enable-AdAuditPolicy.ps1 -VerifyOnly

# Что перенести в групповую политику, чтобы настройки
# пережили следующее её применение
.\Enable-AdAuditPolicy.ps1 -ShowGpoSettings

Скрипт применяет локально

Настройки действуют немедленно, но следующее применение групповой политики может их перезаписать. Для постоянного режима те же параметры задаются в Default Domain Controllers Policy — состав выводится ключом -ShowGpoSettings и продублирован ниже.

Развёртывание платформы

Администратор платформы 40 мин

Всё ставится Ansible. Руками на машину заходить не нужно — и не нужно ничего доустанавливать.

Подготовка управляющей машины

sudo apt install ansible python3-pip

# Распаковать комплект проекта на управляющую машину
cd <каталог проекта>/ansible

Секреты

cp group_vars/vault.yml.example group_vars/vault.yml

# Ключ кластера — ровно 32 символа
openssl rand -hex 16
# Пароли — по одному на каждую учётную запись из файла.

Инвентарь пилота — отдельный

-i inventory/pilot/hosts.yml обязателен в каждой команде. У пилота свои параметры: один шард, ноль реплик, хранение 90 суток, включённый приём syslog. Запуск с боевым инвентарём поставит другую конфигурацию.

Шаг выполнен, если

# Кластер отвечает, статус green (одному узлу реплики не нужны)
curl -k -u admin:ПАРОЛЬ https://<адрес>:9200/_cluster/health?pretty

# Службы менеджера запущены
ssh ansible@<адрес> sudo /var/ossec/bin/wazuh-control status

# Интерфейс открывается
# https://<адрес> — вход под admin

Самопроверка правил проходит внутри установки: если хоть одно собственное правило не сработало на образце события, play прервётся. Молчащее правило внешне неотличимо от правила, для которого не было событий, — поэтому проверка встроена.

Агенты: два контроллера домена и три узла Bitrix

Дулепов Цеховской Администратор 30 мин

Узлы Bitrix — одной командой

ansible-playbook -i inventory/pilot/hosts.yml \
                 playbooks/agents-linux.yml --ask-vault-pass

Агент читает журналы nginx и приложения заявок локально и дополнительно следит за каталогом /home/bitrix/www. Настраивать пересылку журналов не нужно — агент делает больше при меньшем объёме работы.

Контроллеры домена

# На каждом контроллере, от имени администратора
.\Install-WazuhAgent.ps1 -Manager <адрес пилота> `
                         -Group 'default,windows,dc' `
                         -RegistrationPassword '<пароль регистрации>'

Пароль регистрации — тот, что задан в хранилище секретов при развёртывании: 

ansible-vault view group_vars/vault.yml | grep vault_agent_enrollment_password

Параметр -Manager обязателен

По умолчанию скрипт направляет агент на виртуальный адрес отказоустойчивой схемы, которого в пилоте нет. Без явного указания адреса агент установится и не подключится.

Шаг выполнен, если

5

Наблюдение: две недели

Администратор платформы 2 недели

Первая неделя уходит на снятие ложных срабатываний, вторая — на замер фактического потока. Это и есть содержание пилота; установка была подготовкой к нему.

Неделя первая: ложные срабатывания

Каждый день смотреть верхние строки дашборда «AH Prostory — обзор SOC». Правило, которое держится в верхней строке несколько дней подряд, — кандидат либо на настройку, либо на устранение причины. 

# Что срабатывает чаще всего
curl -sk -u admin -H 'Content-Type: application/json' \
  'https://<адрес>:9200/wazuh-alerts-*/_search' -d '{
  "size": 0,
  "query": {"range": {"timestamp": {"gte": "now-24h"}}},
  "aggs": {"правила": {"terms": {"field": "rule.id", "size": 20}}}
}'

Снимается срабатывание не удалением правила, а исключением конкретного случая. Файл rules/ahp_tuning.xml, уровень 0 означает «не поднимать тревогу»: 

<group name="ahp,ahp_tuning,">
  <!-- Служебная задача обходит каталог портала по расписанию -->
  <rule id="100901" level="0">
    <if_sid>100201</if_sid>
    <field name="syscheck.path" type="pcre2">^/home/bitrix/www/bitrix/tmp/</field>
    <description>Служебный каталог: изменения ожидаемы</description>
  </rule>
</group>
# Раскатать и проверить
ansible-playbook -i inventory/pilot/hosts.yml site.yml \
                 --tags content --ask-vault-pass

Исключение должно быть узким

Правило с уровнем 0 на весь каталог портала снимет и настоящую подмену кода. Исключается конкретный путь, конкретная учётная запись, конкретная задача — и с комментарием, почему.

Неделя вторая: замер потока

Главный измеримый результат пилота. Расчёт в документации сделан по типовым значениям; фактические числа позволят заказать железо под отказоустойчивую схему точно, а не с запасом вслепую. 

# Событий в сутки — по дням, за две недели
curl -sk -u admin -H 'Content-Type: application/json' \
  'https://<адрес>:9200/wazuh-alerts-*/_search' -d '{
  "size": 0,
  "query": {"range": {"timestamp": {"gte": "now-14d"}}},
  "aggs": {"по_дням": {"date_histogram":
    {"field": "timestamp", "calendar_interval": "day"}}}
}'

# Объём индексов: сколько места занимает сутки
curl -sk -u admin \
  'https://<адрес>:9200/_cat/indices/wazuh-alerts-*?v&h=index,docs.count,store.size&s=index'

# Поток на менеджере: обработано и отброшено
ssh ansible@<адрес> sudo cat /var/ossec/var/run/wazuh-analysisd.state

Что записать по итогам

  • Событий в секунду: среднее и пиковое
  • Объём индексов в сутки, в гигабайтах
  • Доля событий, ставших алертами
  • Значение events_dropped — должно оставаться нулём
  • Заполнение очереди разбора — должно быть заметно ниже 0.8
  • Список снятых ложных срабатываний с причинами

Приёмка пилота

Проверяется не «установилось ли», а «работает ли как задумано».

  • Интерфейс открывается, вход выполняется
  • События с обоих контроллеров домена доходят и разбираются
  • События со всех узлов Bitrix доходят и разбираются
  • Неверный пароль на контроллере домена поднимает алерт
  • Новый файл в каталоге портала поднимает правило 100202
  • Дашборды показывают данные, а не пустые панели
  • Метрики платформы приходят в Zabbix
  • Ежедневная копия конфигурации создаётся
  • Замерены фактический поток и суточный объём
  • Ложные срабатывания сняты, исключения описаны в репозитории

Что дальше

Пилот не выбрасывается. Правила, снятые ложные срабатывания, дашборды и настройки переезжают в отказоустойчивую схему без изменений — они лежат в репозитории, а не в машине.

ЧтоКак переезжает
Правила, декодеры, исключениябез изменений
Дашбордыбез изменений
Агентыперерегистрация на новый адрес
Сама машина пилотастановится узлом схемы либо остаётся стендом
Исторические событияснапшотом, если нужны
Срок храненияменяется с 90 суток на 400

Решение о переходе принимается по итогам замера: фактический поток покажет, хватит ли расчётных объёмов или их надо пересматривать. Схема отказоустойчивого варианта и разнос по площадкам описаны в документации проекта.

Что принимается сознательно

РискСледствиеЧем закрывается на пилоте

Здесь те же скрипты, что лежат в комплекте проекта, — полностью. Чтобы воспользоваться: скопировать, сохранить под указанным именем, для файлов .sh добавить право на выполнение (chmod +x).

New-WazuhPilotVM.ps1

Создаёт виртуальную машину и снимает четыре настройки Hyper-V по умолчанию, которые мешают: динамическую память, шаблон Secure Boot, автоматические контрольные точки и синхронизацию времени от гипервизора.

Запускается на pdc-hv0, в консоли от администратора · путь в проекте: scripts/pilot/New-WazuhPilotVM.ps1 · 193 строк

<#
.SYNOPSIS
    Создание виртуальной машины пилота Wazuh на Hyper-V.

.DESCRIPTION
    Создаёт машину с параметрами, подобранными под задачу, и снимает
    четыре настройки Hyper-V по умолчанию, которые здесь мешают:

      1. Динамическая память — несовместима с кучей JVM: гипервизор
         отбирает страницы, которые машина считает своими, и сборка
         мусора начинает работать с диском.
      2. Шаблон Secure Boot по умолчанию — с ним Ubuntu не загрузится.
      3. Автоматические контрольные точки — включены по умолчанию в
         Windows Server 2019 и новее, заметно замедляют диск.
      4. Синхронизация времени от гипервизора — конфликтует с NTP
         домена, а расхождение часов ломает корреляцию событий.

    Скрипт идемпотентен: если машина с таким именем уже есть, он
    ничего не пересоздаёт, а сообщает об этом.

.PARAMETER Name
    Имя виртуальной машины. По умолчанию wazuh-pilot.

.PARAMETER SwitchName
    Виртуальный коммутатор серверной сети.

.PARAMETER Path
    Том, где размещаются машины и диски.

.PARAMETER IsoPath
    Установочный образ Ubuntu Server 24.04 LTS.

.EXAMPLE
    .\New-WazuhPilotVM.ps1 -SwitchName "SET-Wazuh" -Path "D:\Hyper-V" `
                           -IsoPath "D:\ISO\ubuntu-24.04-live-server-amd64.iso"

.EXAMPLE
    # Отказоустойчивая схема: узел индексера с диском на 1 ТБ

check_disk() {
    local dev="$1" label="$2"

    [ -b "$dev" ] || die "$dev не является блочным устройством"

    local name; name="$(basename "$dev")"
    if [ -n "$root_disk" ] && [ "$name" = "$root_disk" ]; then
        die "$dev — системный диск. Отказываюсь размечать."
    fi

        if [ "$mp" = "$label" ]; then
            ok "$dev уже смонтирован в $label"
            return 1        # уже готов, размечать не надо
        fi
        die "$dev смонтирован в $mp — не тот том"
    fi

    local fstype; fstype="$(blkid -o value -s TYPE "$dev" 2>/dev/null || true)"
    local parts;  parts="$(lsblk -no NAME "$dev" | tail -n +2 | wc -l)"

    if { [ -n "$fstype" ] || [ "$parts" -gt 0 ]; } && [ "$FORCE" -eq 0 ]; then

mount_by_uuid() {
    local dev="$1" mp="$2" do_format="$3"

    if [ "$do_format" -eq 1 ]; then
        mkfs.xfs -f -q "$dev" || die "не удалось создать файловую систему на $dev"
        ok "файловая система создана на $dev"
    fi

    mkdir -p "$mp"

    local uuid; uuid="$(blkid -o value -s UUID "$dev")"
    [ -n "$uuid" ] || die "не удалось получить UUID для $dev"

    # Монтирование по UUID, а не по имени: sdb и sdc могут поменяться
    # местами после перезагрузки, и данные окажутся не на своём месте.
    sed -i "\|[[:space:]]${mp}[[:space:]]|d" /etc/fstab
    echo "UUID=${uuid}  ${mp}  xfs  defaults,noatime  0 2" >> /etc/fstab

    mountpoint -q "$mp" || mount "$mp" || die "не удалось смонтировать $mp"
    ok "$mp смонтирован (UUID=${uuid})"
}

fi

    ok "источник времени: ${NTP_SERVER}"
fi

systemctl enable --now chrony >/dev/null 2>&1
systemctl restart chrony

printf '  ждём синхронизации'
for _ in $(seq 1 30); do
    [ "$(timedatectl show -p NTPSynchronized --value)" = "yes" ] && break
    printf '.'; sleep 2
done
printf '\n'

if [ "$(timedatectl show -p NTPSynchronized --value)" = "yes" ]; then

else

fi

step "5. Учётная запись для Ansible"
# ---------------------------------------------------------------------
if ! id "$ANSIBLE_USER" >/dev/null 2>&1; then

    ok "учётная запись $ANSIBLE_USER создана"
else

touch "$home/.ssh/authorized_keys"

<#
.SYNOPSIS
    Установка агента Wazuh на узел Windows.

.DESCRIPTION
    Рассчитан на массовую раскатку через групповую политику: скрипт
    идемпотентен, при повторном запуске на уже настроенной машине
    ничего не делает и завершается кодом 0.

    Что делает:
      1. Проверяет, не установлен ли агент нужной версии.
      2. Скачивает пакет с сетевого ресурса или из интернета.
      3. Устанавливает с параметрами регистрации (адрес менеджера,
         имя агента, группы).
      4. Дожидается подключения к менеджеру и проверяет его.
      5. Пишет результат в журнал приложений Windows — по нему видно,
         на скольких машинах политика отработала.

    Группа агента определяется автоматически по роли машины: рабочая
    станция, сервер, контроллер домена. От группы зависит набор
    собираемых журналов — см. rules/agent-groups/.

.PARAMETER Manager
    Адрес приёма агентов. По умолчанию VIP балансировщика.

.PARAMETER RegistrationPassword
    Пароль регистрации (authd). При раскатке через GPO передаётся
    из защищённого файла на сетевом ресурсе, доступном на чтение
    только компьютерам домена.

.PARAMETER Group
    Группы агента через запятую. Если не указано — определяются
    автоматически.

.EXAMPLE
    .\Install-WazuhAgent.ps1 -RegistrationPassword 'пароль'

.EXAMPLE
    .\Install-WazuhAgent.ps1 -Group 'default,windows,dc' -Force
#>

param(

    [string]$Version = '4.14.7',

# ---------------------------------------------------------------------
# Журналирование
# ---------------------------------------------------------------------
function Write-Log {
    param([string]$Message, [ValidateSet('Information','Warning','Error')][string]$Level = 'Information')

    Write-Host "[$(Get-Date -Format 'HH:mm:ss')] $Message"

    try {
        if (-not [System.Diagnostics.EventLog]::SourceExists($EventSource)) {
            New-EventLog -LogName Application -Source $EventSource
        }
        $id = switch ($Level) { 'Error' { 3001 } 'Warning' { 3002 } default { 3000 } }
        Write-EventLog -LogName Application -Source $EventSource -EntryType $Level `
                       -EventId $id -Message $Message
    } catch {
        # Журнал недоступен — не повод прерывать установку
    }
}

# ---------------------------------------------------------------------
# Определение групп по роли машины
# ---------------------------------------------------------------------
function Get-AgentGroups {
    $os = Get-CimInstance Win32_OperatingSystem
    $groups = @('default', 'windows')

    switch ($os.ProductType) {
        1 { $groups += 'workstation' }        # рабочая станция
        2 { $groups += 'dc' }                 # контроллер домена
        3 {                                    # рядовой сервер
            if (Get-Service -Name 'vmms' -ErrorAction SilentlyContinue) {
                $groups += 'hyperv'
            }
            if (Get-Service -Name 'MSSQLSERVER' -ErrorAction SilentlyContinue) {
                $groups += 'mssql'
            }
        }
    }

    return ($groups -join ',')
}

# Проверка текущего состояния

function Get-InstalledVersion {
    $service = Get-Service -Name 'WazuhSvc' -ErrorAction SilentlyContinue
    if (-not $service) { return $null }

    $verFile = Join-Path $AgentDir 'VERSION'
    if (Test-Path $verFile) {
        return ((Get-Content $verFile -Raw).Trim() -replace '^v', '')
    }
    return 'неизвестна'
}

# Основной поток
# ---------------------------------------------------------------------
try {
    $identity = [Security.Principal.WindowsIdentity]::GetCurrent()
    $principal = New-Object Security.Principal.WindowsPrincipal($identity)
    if (-not $principal.IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)) {
        throw 'Нужны права администратора.'
    }

    $installed = Get-InstalledVersion
    if ($installed -and -not $Force) {
        if ($installed -eq $Version) {
            Write-Log "Агент версии $Version уже установлен. Ничего не делаю."
            exit 0
        }
        Write-Log "Установлена версия $installed, требуется $Version. Обновляю." -Level Warning
    }

    if (-not $Group) {
        $Group = Get-AgentGroups
    }
    Write-Log "Группы агента: $Group"

    # --- Пароль регистрации ------------------------------------------
    if (-not $RegistrationPassword) {
        if (Test-Path $PasswordFile) {
            $RegistrationPassword = (Get-Content $PasswordFile -Raw).Trim()
        } else {
            throw "Не задан пароль регистрации и недоступен $PasswordFile"
        }
    }

    # --- Пакет --------------------------------------------------------
    $msiName = "wazuh-agent-$Version-1.msi"
    $localMsi = Join-Path $env:TEMP $msiName
    $sourceMsi = Join-Path $PackageSource $msiName

    if (Test-Path $sourceMsi) {
        Write-Log "Копирую пакет с $PackageSource"
        Copy-Item -Path $sourceMsi -Destination $localMsi -Force
    } else {
        $url = "https://packages.wazuh.com/4.x/windows/$msiName"
        Write-Log "Пакет на сетевом ресурсе не найден, скачиваю с $url" -Level Warning
        [Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
        Invoke-WebRequest -Uri $url -OutFile $localMsi -UseBasicParsing
    }

    if (-not (Test-Path $localMsi)) {
        throw "Пакет установки не получен: $msiName"
    }

    # --- Установка ----------------------------------------------------
    # Параметры регистрации передаются в msiexec: агент регистрируется
    # сам при первом запуске службы.
    $arguments = @(
        '/i', "`"$localMsi`"",
        '/q',
        "WAZUH_MANAGER=`"$Manager`"",
        "WAZUH_REGISTRATION_SERVER=`"$Manager`"",
        "WAZUH_REGISTRATION_PASSWORD=`"$RegistrationPassword`"",
        "WAZUH_AGENT_NAME=`"$env:COMPUTERNAME`"",
        "WAZUH_AGENT_GROUP=`"$Group`"",
        'WAZUH_PROTOCOL="tcp"',
        "/l*v `"$env:TEMP\wazuh-agent-install.log`""
    )

    Write-Log "Устанавливаю агент $Version, менеджер $Manager"
    $process = Start-Process -FilePath 'msiexec.exe' -ArgumentList $arguments -Wait -PassThru -NoNewWindow

    if ($process.ExitCode -ne 0) {
        throw "msiexec завершился кодом $($process.ExitCode). Подробности: $env:TEMP\wazuh-agent-install.log"
    }

    Remove-Item $localMsi -Force -ErrorAction SilentlyContinue

    # --- Запуск и проверка --------------------------------------------
    Start-Service -Name 'WazuhSvc' -ErrorAction SilentlyContinue
    Set-Service -Name 'WazuhSvc' -StartupType Automatic

    Write-Log 'Жду подключения к менеджеру...'
    $logFile = Join-Path $AgentDir 'ossec.log'
    $connected = $false

    for ($i = 0; $i -lt 24; $i++) {
        Start-Sleep -Seconds 5
        if (Test-Path $logFile) {
            $tail = Get-Content $logFile -Tail 60 -ErrorAction SilentlyContinue
            if ($tail -match 'Connected to the server') {
                $connected = $true
                break
            }
            if ($tail -match 'Unable to add agent|Invalid password') {
                throw 'Регистрация отклонена менеджером: неверный пароль или имя агента занято.'
            }
        }
    }

    if ($connected) {
        Write-Log "Агент установлен и подключён к $Manager. Группы: $Group"
        exit 0
    }

    Write-Log "Агент установлен, но подключение к $Manager за 2 минуты не подтверждено. Проверить доступность портов 1514 и 1515." -Level Warning
    exit 0

} catch {
    Write-Log "Установка не удалась: $($_.Exception.Message)" -Level Error
    exit 1
}

Enable-AdAuditPolicy.ps1

Включает расширенный аудит, командную строку в событии 4688 и запись блоков PowerShell, увеличивает журнал безопасности. Без этого события не создаются вовсе.

Запускается на каждом контроллере домена, от администратора · путь в проекте: scripts/pilot/Enable-AdAuditPolicy.ps1 · 251 строк

<#
.SYNOPSIS
    Включение расширенного аудита на контроллере домена.

.DESCRIPTION
    Без этих политик события 4688, 4769 и 4104 не создаются вовсе, и
    собирать будет нечего — каким бы способом события ни доставлялись
    в Wazuh. Это первое, что делается при подключении Active Directory,
    и оно не зависит от готовности сервера Wazuh.

    Скрипт настраивает:
      * подкатегории расширенного аудита (auditpol);
      * запись командной строки в событие 4688 — без неё видно имя
        процесса, но не аргументы, и правила на обфусцированный
        PowerShell и удаление теневых копий бесполезны;
      * запись блоков сценариев PowerShell (события 4103 и 4104);
      * размер журнала безопасности — на контроллере домена журнал по
        умолчанию перекрывается за часы, и события пропадают раньше,
        чем их успевают забрать.

    Применяется немедленно и на пилоте из двух контроллеров этого
    достаточно. Для постоянного режима те же параметры задаются
    групповой политикой Default Domain Controllers Policy — иначе
    следующее применение политики их перезапишет. Состав политик для
    ручного переноса выводится ключом -ShowGpoSettings.

.PARAMETER WhatIf
    Показать, что было бы изменено, ничего не меняя.

.PARAMETER VerifyOnly
    Только проверить текущее состояние.

.PARAMETER SecurityLogSizeMB
    Размер журнала безопасности. По умолчанию 1024 МБ.

.EXAMPLE
    .\Enable-AdAuditPolicy.ps1 -VerifyOnly

.EXAMPLE
    .\Enable-AdAuditPolicy.ps1
#>

# ---------------------------------------------------------------------
Write-Step "Подкатегории аудита"
# ---------------------------------------------------------------------
$applied = 0
foreach ($sub in $Subcategories) {
    $current = (auditpol /get /subcategory:"$($sub.Guid)" /r 2>$null | ConvertFrom-Csv)
    $now     = if ($current) { $current.'Inclusion Setting' } else { 'неизвестно' }

    if ($VerifyOnly) {
        if ($now -match 'Success|Failure|Успех|Отказ') { Write-Ok "$($sub.Name): $now" }
        else { Write-No "$($sub.Name): $now" }
        continue
    }

    $modeSpec = $sub.Mode -replace '^enable:', ''
    $success  = if ($modeSpec -match 'success') { 'enable' } else { 'disable' }
    $failure  = if ($modeSpec -match 'failure') { 'enable' } else { 'disable' }

    if ($PSCmdlet.ShouldProcess($sub.Name, "auditpol /set")) {
        $null = auditpol /set /subcategory:"$($sub.Guid)" /success:$success /failure:$failure 2>&1

        # Читаем обратно: при неверном идентификаторе auditpol не всегда
        # возвращает ошибку, но и не применяет ничего — это надо увидеть
        $after = (auditpol /get /subcategory:"$($sub.Guid)" /r 2>$null | ConvertFrom-Csv)
        if ($LASTEXITCODE -eq 0 -and $after -and
            $after.'Inclusion Setting' -match 'Success|Failure|Успех|Отказ') {
            Write-Ok "$($sub.Name) → $($after.'Inclusion Setting')"
            $applied++
        } else {
            Write-No "$($sub.Name): не применилось — проверьте идентификатор подкатегории"
        }

        else { Write-No "$($r.Why): выключено (значение: $current)" }
        continue

    if ($PSCmdlet.ShouldProcess($r.Why, "установить $($r.Name)=$($r.Value)")) {
